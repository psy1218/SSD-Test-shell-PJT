# NAND 저장 포맷

## 물리 파일 계약

- 최종 파일명: `nand.txt`
- 내용: 바이너리 (`.txt` 확장자는 교육 명세 호환용)
- 헤더: 없음
- 전체 길이: 정확히 400바이트
- LBA 개수: 100
- LBA당 크기: 4바이트
- 바이트 순서: Little Endian
- 체크섬: 없음

LBA `n`의 시작 오프셋은 `n * 4`다. 따라서 LBA 0은 offset 0,
LBA 99는 offset 396에서 시작한다.

예를 들어 LBA 3에 `0x12345678`을 기록하면 offset 12부터 다음 바이트가
저장된다.

```text
78 56 34 12
```

## 생성 및 손상 처리

- 파일이 없으면 400개의 0 바이트로 새로 만든다.
- 정상 크기의 파일은 기존 데이터를 유지한다.
- 400바이트가 아닌 파일은 손상으로 보고한다.
- 손상 파일은 자동 초기화하거나 덮어쓰지 않는다.

## 갱신 정책과 한계

한 LBA만 바꾸더라도 전체 400바이트 이미지를 임시 파일에 기록한 뒤
`rename()`으로 교체한다. 동일 파일시스템에서의 교체 전 실패로부터 원본을
보호하기 위한 정책이다.

파일 데이터에는 `fsync()`를 수행하지만 부모 디렉터리까지 동기화하지는 않는다.
따라서 이 구현은 프로세스 수준 실패에 대한 안전성을 개선하지만 갑작스러운
전원 차단에서의 완전한 내구성을 보장하지 않는다. 동시 writer도 지원 범위 밖이다.
