# 한계 및 개선 방향

## 프로젝트의 경계

이 프로젝트는 SSD 검증 자동화의 소프트웨어 구조를 학습하기 위한 파일 기반
시뮬레이터다. 실제 NAND 플래시나 NVMe 컨트롤러를 구동하지 않으며, 측정 결과를
실물 SSD의 성능이나 신뢰성 지표로 해석하지 않는다.

## 현재 한계

### 하드웨어 모델 단순화

LBA 100개와 400바이트 파일만 모델링한다. NAND Page/Block, erase-before-write,
ECC, bad block, Wear Leveling, Garbage Collection, 수명 및 온도 특성은 포함하지
않는다.

### 동시성

기준 실행은 순차 명령이다. 여러 SSD 프로세스가 같은 `nand.txt`에 동시에
쓰기 시작할 때의 lost update나 파일 잠금은 보장하지 않는다.

### 장애 내구성

Write는 임시 파일 작성, `fsync()`, `rename()`을 사용해 교체 중 원본 손상
가능성을 낮춘다. 그러나 모든 전원 장애 시점, 저장장치 캐시, 파일시스템 동작에
대한 원자성과 내구성을 증명하지는 않는다.

### 프로토콜 비용

교육 명세에 따라 매 명령마다 SSD 프로세스를 실행하고 Read 값을 파일로
전달한다. 대량 테스트에서는 프로세스 생성과 동기 파일 I/O가 실제 400바이트
데이터 처리보다 큰 비용이 될 수 있다.

### 플랫폼

Linux/POSIX를 공식 기준으로 한다. WSL에서는 동작하지만 Windows 네이티브 API,
MSVC, 경로 규칙은 지원하지 않는다.

### 테스트 범위

현재 Mutation Score 100%는 의도적으로 만든 두 결함에 대한 결과다. 모든 가능한
결함을 검출한다는 의미가 아니며, mutation 종류가 늘어나면 점수는 달라질 수 있다.

## 우선순위별 확장 방향

1. 파일 잠금과 충돌 테스트를 추가해 동시 Write 계약을 정의한다.
2. Read 결과를 pipe로 전달하는 실험 버전을 만들어 파일 프로토콜 비용을 분리한다.
3. mutation 종류를 truncation, byte-order, stale result, partial write로 확대한다.
4. timeout과 강제 종료 정책을 추가해 멈춘 SSD 프로세스를 ERROR로 회수한다.
5. Linux 네이티브 파일시스템에서도 같은 벤치마크를 실행해 WSL 마운트 영향을 비교한다.
6. 필요하면 Page/Block 계층을 별도 모델로 추가하되 기존 LBA 계약과 분리한다.

확장은 기준 구현의 재현성과 교육 명세를 깨지 않는 별도 실험으로 진행하는 것이
적절하다.
