# 자동 테스트 계획

## 목적

SSD가 명령을 실행했다는 사실이 아니라, 명세에서 계산한 기대값과 실제값이
일치하는지 독립적으로 판정한다. 테스트가 사용자 데이터를 훼손하거나 이전
테스트의 결과에 의존하지 않도록 실행 환경을 격리한다.

## Oracle 규칙

1. 각 테스트 시작 시 100개 기대값을 모두 0으로 초기화한다.
2. SSD Write 종료 코드가 0일 때만 기대값을 갱신한다.
3. SSD Read 실패는 값 비교 전에 ERROR로 처리한다.
4. 실제값은 `result.txt`의 정확한 한 줄 형식을 검사한 후 파싱한다.
5. 기대값 생성에 `nand.txt`나 SSD 저장 함수를 사용하지 않는다.

## 테스트 격리

- 각 케이스는 `/tmp/ssd-validation-XXXXXX`에서 실행한다.
- SSD 경로는 작업 디렉터리 변경 전에 절대 경로로 변환한다.
- 테스트 종료 후 `nand.txt`, `result.txt`, 임시 디렉터리를 제거한다.
- 사용자 작업 디렉터리의 NAND는 자동 테스트가 읽거나 쓰지 않는다.

## 실행 모드

```sh
./testshell --run-tests
./testshell --run-test TC-F001
./testshell --ssd-path ./ssd_fault_boundary --run-tests
```

비대화형 종료 코드:

- 0: 실행한 테스트 모두 PASS
- 1: FAIL 하나 이상
- 2: 실행 환경 ERROR 또는 잘못된 테스트 ID

## TestApp 시나리오

### TestApp1

1. LBA 0~99에 `0xA5A5A5A5` 기록 및 전체 비교
2. LBA별 `0xA5000000 | lba` 기록 및 전체 비교
3. 주소 매핑과 LBA 99 경계를 함께 검증

### TestApp2

1. LBA 0~5 순회를 5회 반복해 `0xAAAABBBB` 30회 기록
2. 같은 LBA 0~5에 `0x12345678`로 덮어쓰기
3. 최종 여섯 값을 독립 기대값과 비교

## 보고서

각 실행은 테스트 ID, 요구사항 ID, SSD 경로, 상태, 시간, 기대값, 실제값,
실패 이유, 재현 명령을 가능한 범위에서 기록한다. 보고서는 로그 텍스트,
요약 텍스트, CSV, Markdown으로 생성한다.
